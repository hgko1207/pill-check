## Problem Statement

아버지가 TV 홈쇼핑이나 건강 프로그램에서 "비피더스 B-3가 좋다" 같은 말을 들으면, 그게 정말인지, 어떤 제품에 들어 있는지, 지금 드시는 약과 같이 먹어도 되는지를 매번 자녀에게 물어보신다. 네이버로 찾으면 광고 글뿐이고, 제품마다 원료가 뭔지 확인하기 어렵다.

## What Makes This Cool

**"이 제품, TV에서 말한 그 성분 진짜 들어 있어?"에 식약처 원문으로 답한다.**

시험 데이터에서 실제로 나온 장면: "B-3 다이어트 유산균"을 찾으면 쓰리핏, 비에날씬, 비피움 비쓰리가 같이 나온다. 식약처 원료를 대조하면 **비피움 비쓰리만 B-3가 맞고, 쓰리핏(CJLP133)과 비에날씬(BNR17)은 다른 균**이다. 광고만 봐서는 알 수 없는 사실을 한 화면에 보여 주는 것, 그게 이 앱만의 순간이다.

## Constraints

- 솔로 사이드 프로젝트, 부모님이 직접 사용 (60대 UX: 큰 글씨, 한 화면 핵심 3개 이하)
- 쇼핑 가격 API 없음: 네이버 쇼핑 검색 API는 2026-07-31 종료, 쿠팡 파트너스는 판매 실적·호출 한도 조건 때문에 보류 (`docs/next-supplement-search.md` "가격 API를 쓰지 않는 이유")
- 식약처 품목 API(`I0030`)는 **제품명(`PRDLST_NM`)으로만 걸러진다**. 원료·기능성 필터는 무시된다 (2026-11-10 `filter-test.mjs` 실행 결과)
- 식약처 데이터의 업체는 **제조 공장(OEM)**이고 판매 브랜드가 없다
- 의료 인접: "안전하다" 단정 금지, 면책 문구 유지, 판정은 데이터 근거로만

## Premises (2026-11-11 사용자 동의)

1. 1단계가 답할 질문은 "TV에서 들은 그 제품·성분, 진짜야?"다. 답은 식약처 사실(인정 기능, 원료, 함량, 회수 이력)과 내 약 충돌이다. 가격은 쇼핑몰 검색 버튼으로만 둔다.
2. "성분 → 판매 중 제품 순위"는 지금 데이터로 못 만든다(판매 확인 14%, ? 포함 48%). 1단계에서 빼고 5월 설계대로 '비교'는 V2로 둔다.
3. 입력은 제품명 검색이 1순위다(TV는 이름으로 들음). 영양제 바코드는 지금 사실상 동작하지 않는다(`SearchScreen.tsx` `handleScan`이 바코드 숫자를 제품명 검색에 넣음, `I0030`에 바코드 필드 없음). 바코드 → 제품 데이터는 따로 확인한다.
4. "이 제품에 B-3가 들어 있나" 판정은 LLM이 아니라 식약처 원료명 글자 대조로 한다. 대조할 수 없으면 "확인 못 함"으로 표시한다.
5. 새 홈 화면을 만들지 않고 지금 검색 화면·상세 창·충돌 카드를 넓힌다.

## Approaches Considered

- **A. 제품 상세 보강만**: 원료·기능성·함량·회수·가격 버튼. 가장 빠르지만 성분 확인을 사용자가 원료 목록을 직접 읽어서 해야 한다. B에 포함됨.
- **B. TV 말 확인 (선택)**: A + 성분 대조 + 성분 설명 카드.
- **C. 바코드 완성**: A + 바코드 → 제품 연결. 식품안전나라 바코드 서비스(`C005`, `I2570`)가 존재는 하나 활용신청이 안 돼 있어 내용 미확인(2026-11-10 `probe.mjs`: "활용신청 내역이 없습니다"). 신청 후 별도 단계로 붙인다.
- 기각: 성분 → 판매 중 제품 순위 (시험 실패), 네이버·쿠팡 가격 API (위 제약)

## Recommended Approach: B

### 1. 제품 상세 보강 (영양제)

`DetailModal`의 영양제 상세에 아래를 보여 준다. 모두 `I0030` 응답에 이미 있는 필드다.

| 항목 | 출처 필드 | 비고 |
|---|---|---|
| 주된 기능성 | `PRIMARY_FNCLTY` | 식약처 문구 그대로 |
| 원료 | `RAWMTRL_NM`, `INDIV_RAWMTRL_NM` | 대조 결과로 강조 |
| 함량 | `STDR_STND`의 "표시량" 줄 | 제품 무게당 표시량(예: 16mg/250mg). 하루 섭취량 환산은 1단계에서 하지 않는다 |
| 섭취 방법·주의사항 | `NTK_MTHD`, `IFTKN_ATNT_MATR_CN` | |
| 제조 | `BSSH_NM` | "제조: ○○"로 표시 (판매 브랜드 아님) |
| 회수 이력 | `I0490` | 품목보고번호 일치, 없으면 제품명+업체 일치. 있으면 빨간 표시 |
| 가격 보기 | 없음 | [네이버에서 가격 보기] [쿠팡에서 가격 보기] = 제품명으로 쇼핑몰 검색 페이지 열기 |

검색 결과에서 같은 제품명(공장만 다른 신고)은 하나로 묶는다.

### 2. 성분 대조 ("TV에서 들은 성분 확인")

- 영양제 상세에 "TV에서 들은 성분 확인" 영역을 둔다. 자주 나오는 성분 칩(B-3, 루테인, 비타민 D, 밀크씨슬, 오메가3 …)을 누르거나 직접 입력한다.
- 결과는 세 가지 중 하나로 크게 보여 준다.
  - ✅ **들어 있어요**: 원료에서 일치한 원문을 같이 보여 준다 (예: "Bifidobacterium breve B-3")
  - ❌ **이 제품 원료에는 없어요**: 대신 들어 있는 주요 원료를 보여 준다 (예: "L.plantarum CJLP133")
  - **확인 못 했어요**: 별칭표에 없는 성분이거나 원료 칸이 비었을 때. 약사 확인 안내
- 판정은 `web/src/lib/`의 **성분 별칭표**(성분별 정규식, `scripts/gate-search/gate.mjs`의 `INGREDIENTS`에서 시작)로 원료명을 대조한다.
- 문구: "식약처 신고 원료 기준이에요. 효과를 보장하지 않아요." 를 결과 아래에 둔다.

### 3. 성분 설명 카드

- 검색어가 별칭표의 성분이면 검색 결과 맨 위에 카드를 띄운다: 성분 이름, 식약처 인정 기능성, 섭취 시 주의사항, "이 성분이 원료인 신고 제품 ○개".
- 제품 수와 대표 기능성 문구는 실시간 API로 셀 수 없다(원료 필터 불가). `scripts/`에서 `I0030` 전체로 **작은 정적 JSON**(성분별 요약)을 만들어 `web/`에 넣는다. 갱신은 수동.
- 카드에 판매 제품 목록이나 순위는 넣지 않는다.

### 그대로 쓰는 것

- 내 약 충돌: 기존 `dur.ts`, `InteractionResultCard`
- 제품명 검색: 기존 `healthfood-api.ts`의 `searchHealthFood` (`PRDLST_NM` 필터)

## Open Questions

1. **성분 설명의 "인정 기능성" 문구 출처**: 고시형 원료는 식약처 고시 문구가 있고, 개별인정형(B-3 = 제2023-2호)은 인정 문구가 따로 있다. 제품들의 `PRIMARY_FNCLTY`에서 가장 흔한 문구를 쓸지, 고시·인정 원문 데이터를 찾을지 계획 단계에서 정한다.
2. **별칭표 범위**: 1단계에 몇 개 성분을 넣을지. 시작은 시험한 5개 + 홈쇼핑 단골(예: 홍삼, 프로바이오틱스 일반, 콘드로이친, MSM, 코엔자임Q10)을 후보로 둔다.
3. **바코드(대안 C)**: `C005`·`I2570` 활용신청 후 바코드 → 품목보고번호가 있는지, 영양제 커버리지가 얼마인지 확인.
4. **정적 JSON 크기·갱신 주기**: 성분 10~20개 요약이면 수 KB로 예상. 월 1회 수동 갱신으로 충분한지.

## Success Criteria

- 아버지가 TV에서 들은 제품 이름을 직접 입력해서, 그 성분이 들어 있는지(✅/❌/확인 못 함)를 도움 없이 1분 안에 확인한다.
- 시험 데이터 기준 성분 대조가 맞다: 비피움 비쓰리 = B-3 ✅, 쓰리핏·비에날씬 = B-3 ❌, 시험 5성분 상위 제품 대조 결과가 원료 원문과 일치.
- 회수 이력이 있는 제품(시험에서 밀크씨슬 2건)은 빨간 표시가 뜬다.
- 결과 화면 어디에도 "안전", "추천", "효과 좋은" 같은 단정·권유 문구가 없고 면책 문구가 보인다.
- `npm --prefix web run typecheck`와 `npm --prefix web run build` 통과.

## What I noticed about how you think

- 판매 확인을 직접 하라고 했을 때 "실제로 판매되는지 다 내가 열어보라고? 자동화나 뭐 검증을 해야지 네가"라고 바로 되물었다. 사람이 손으로 확인해야 하는 단계를 그대로 두지 않는다.
- 네이버가 막히자 "차라리 네이버 말고 쿠팡으로해?"로 곧장 다른 길을 찾았다. 막힌 지점에서 멈추지 않고 대안을 먼저 꺼낸다.
- 성분을 고를 때 "홈쇼핑또는 그 건강 프로그램이 있자나 그런거"라고 했다. 기능 목록이 아니라 아버지가 실제로 무엇을 보고 묻는지에서 출발한다.
