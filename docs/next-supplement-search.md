## 왜 하는가

아버지가 TV 홈쇼핑에서 "비피더스 B-3가 좋다" 같은 말을 들으면 그게 정말 좋은지, 어떤 제품이 있는지, 얼마인지 매번 물어보신다. 네이버로 찾으면 제품마다 들어가 봐야 하고 비교가 안 된다.

**목표 화면**: 성분 이름을 넣으면 지금 판매 중인 영양제가 **회사, 제품명, [네이버·쿠팡에서 가격 보기] 버튼**과 함께 나오고, 우리 기준으로 **좋은 순서**로 정렬된다. 각 제품에는 **식약처 검증**(인정 효과, 함량, 주의사항, 회수 이력)과 **지금 드시는 약과의 충돌**이 붙는다. 큰 글씨, 한 화면.

## 이미 정한 것 (다시 논의하지 않는다)

| 항목 | 결정 |
|---|---|
| 제품, 회사, 인정 효과, 함량, 주의사항 | 식품안전나라 건강기능식품 품목 데이터 (이미 `web/src/lib/healthfood-api.ts`에서 `I0030` 사용 중) |
| 회수·판매중지 이력 | 식품안전나라 회수 정보 `I0490` (2026-11-10 첫 호출로 확인: 391건, 제품명·업체·바코드·회수 사유) |
| 가격 | **앱 안에 가격을 넣지 않는다.** 제품마다 [네이버에서 가격 보기] [쿠팡에서 가격 보기] 버튼으로 각 쇼핑몰 검색 결과 페이지를 연다 (API·키 없음). 아래 "가격 API를 쓰지 않는 이유" 참고 |
| "지금 판매 중" 판단 | 가격 API가 없으므로 식약처 데이터로만 판단한다. 후보: `I0030`의 `PRODUCTION` 필드, 최종 수정일(`LAST_UPDT_DTM`). 2단계에서 의미를 확인한다 |
| **리뷰, 별점** | **가져오지 않는다.** API가 주지 않고, 쇼핑몰 리뷰를 긁는 것은 약관 위반이다. 대신 "리뷰 보러 가기" 버튼으로 네이버 상품 페이지를 연다 |
| **일반의약품** | 가격 비교를 하지 않는다 (약사법상 온라인 판매 불가). 의약품은 지금처럼 허가 정보와 DUR만 보여 준다 |
| 순위 이름 | "효과 좋은 순"이라고 쓰지 않는다. **"함량·신뢰 순"**처럼 기준을 드러내고, 제품마다 점수 이유를 보여 준다 |
| 문구 | "사세요", "추천" 같은 권유를 쓰지 않는다. 식약처 사실만 보여 준다 (건강기능식품 광고 규제) |
| 수익 링크 | 1단계에서는 넣지 않는다. 나중에 제휴 링크를 넣으면 "수수료를 받을 수 있음" 표시가 의무다 |
| 경쟁 앱 | 필라이즈는 다이어트·운동 쪽이라 방향이 다르다(사용자 판단). 우리 차이: 부모님용 큰 글씨, 식약처 검증, 내 약 충돌, 하루치 가격 |

### 1단계. (취소) 네이버 키 준비

2026-11-10 확인: 네이버 쇼핑 검색 API는 2026-07-31 종료됐고 대체 API가 없다(NAVER API HUB에도 쇼핑 검색 없음). 쿠팡 파트너스 API도 지금은 맞지 않는다. 아래 "가격 API를 쓰지 않는 이유" 참고. 키 준비는 하지 않는다.

### 2단계. 가능성 시험 ← 가장 중요

이 기능이 될지 안 될지는 **성분 이름으로 식약처 제품을 제대로 찾을 수 있는가**에 달려 있다. 화면을 만들기 전에 이것부터 확인한다.

**입력 성분 5개**: 비피더스 B-3, 루테인, 비타민 D, 밀크씨슬 (사용자, 홈쇼핑·건강 프로그램에서 나오는 것) + 오메가3 (Claude가 추가, 표기가 여러 가지라 시험용)

**시험 스크립트**: `scripts/gate-search/` 아래 Node 스크립트(의존성 없이 `fetch`). 키는 `web/.env`에서 읽고 로그에 찍지 않는다.

성분마다:
1. **식약처에서 제품 찾기**: 먼저 API가 원재료(`RAWMTRL_NM`, `INDIV_RAWMTRL_NM`)나 기능성으로 걸러 주는지 확인한다. 안 되면 `I0030` 전체(약 4.6만 건)를 페이지 단위로 내려받아 `scripts/gate-search/data/`에 저장한 뒤 로컬에서 찾는다(커밋하지 않음).
2. **함량 읽기**: 기준규격(`STDR_STND`)의 "표시량"에서 성분 함량을 읽을 수 있는지 본다.
3. **판매 중 판단**: `PRODUCTION`, `LAST_UPDT_DTM`이 단종 여부를 가르는 데 쓸 만한지 본다.
4. **소비자용 제품만**: 원료용 품목(예: 섭취방법이 "건강기능식품 원료로 사용")을 걸러낸다.
5. **기록**: 성분별 제품 수, 상위 10개(제품명, 회사, 주된 기능성, 함량, 네이버·쿠팡 검색 링크, 회수 이력 여부)를 표로 정리한다.

**결과물**: `scripts/gate-search/RESULT.md` 표. 사용자가 링크를 눌러 실제 판매 제품이 맞는지 직접 확인한다.

**통과 기준**:
- 성분 5개 중 4개 이상에서, 소비자용 제품을 3개 이상 찾음
- 사용자가 확인했을 때 상위 10개 중 80% 이상이 실제로 판매 중인 제품

**멈춤 조건** (이럴 땐 진행하지 말고 보고한다):
- 성분 이름으로 제품을 찾을 수 없다 (원료 필드가 비었거나 표기가 너무 제각각)
- 상위 목록의 60% 이상이 단종·원료용 제품이다

**끝나면 멈추고 결과를 보고한다.**

### 가격 API를 쓰지 않는 이유 (2026-11-10 조사)

- **네이버**: 쇼핑 검색 API 2026-07-31 종료, 대체 없음. 개발자센터 신규 신청도 같은 날 종료. 남은 검색 API는 2026-09-07 약관부터 결과를 AI에 넣거나 캐싱하는 것을 금지한다고 보도됨. 근거: developers.naver.com 공지 32564·32530(원문 직접 확인 못 함), 네이버 클라우드 API HUB 문서
- **쿠팡 파트너스**: 키 발급에 판매 실적 15만 원 이상 필요(2023년 자료), 검색 API 시간당 10회 제한·초과 시 계정 제한 보고(2025년 자료), 링크가 모두 제휴 링크라 "수수료" 표시 의무. 공식 문서는 로그인 필요로 확인 못 함
- 나중에 쿠팡 키를 받으면 앱 안 가격 표시를 다시 검토한다

> **2026-11-11 결과**: 2단계는 판매 확인 14%로 통과하지 못했다(`scripts/gate-search/SALES-CHECK.md`). `/office-hours`에서 방향을 "TV 말 확인"으로 바꿨다. 이후 단계는 [`docs/designs/tv-claim-check.md`](designs/tv-claim-check.md)를 따른다. 아래 3~4단계의 원래 내용은 기록으로 남긴다.
