> 대상: 이 저장소에서 작업하는 Claude 세션과 사용자. 2026-11-10 ai-setup-service 세션에서 사용자와 정한 내용을 옮겼다.
> 사용법: 새 세션에서 "docs/next-supplement-search.md 읽고 0단계부터 진행해줘"라고 시작한다. 단계마다 끝나면 멈추고 사용자에게 보고한다.

## 왜 하는가

아버지가 TV 홈쇼핑에서 "비피더스 B-3가 좋다" 같은 말을 들으면 그게 정말 좋은지, 어떤 제품이 있는지, 얼마인지 매번 물어보신다. 네이버로 찾으면 제품마다 들어가 봐야 하고 비교가 안 된다.

**목표 화면**: 성분 이름을 넣으면 지금 판매 중인 영양제가 **회사, 제품명, 가격, 네이버 링크**와 함께 나오고, 우리 기준으로 **좋은 순서**로 정렬된다. 각 제품에는 **식약처 검증**(인정 효과, 함량, 주의사항, 회수 이력)과 **지금 드시는 약과의 충돌**이 붙는다. 큰 글씨, 한 화면.

## 이미 정한 것 (다시 논의하지 않는다)

| 항목 | 결정 |
|---|---|
| 제품, 회사, 인정 효과, 함량, 주의사항 | 식품안전나라 건강기능식품 품목 데이터 (이미 `web/src/lib/healthfood-api.ts`에서 `I0030` 사용 중) |
| 회수·판매중지 이력 | 식품안전나라 회수 정보 (서비스 ID는 `I0490`로 알려져 있음. 첫 호출로 확인) |
| 가격, 판매처, 링크, 이미지 | 네이버 쇼핑 검색 API `https://openapi.naver.com/v1/search/shop.json` (헤더 `X-Naver-Client-Id`, `X-Naver-Client-Secret`, 파라미터 `query`, `display` 최대 100, `sort=sim`). 하루 호출 한도가 있으니 결과를 캐시한다 |
| "지금 판매 중" 판단 | 네이버 검색에 나오면 판매 중. 안 나오면 목록에서 뺀다 (식약처 신고 데이터에는 단종 제품도 남아 있다) |
| **리뷰, 별점** | **가져오지 않는다.** API가 주지 않고, 쇼핑몰 리뷰를 긁는 것은 약관 위반이다. 대신 "리뷰 보러 가기" 버튼으로 네이버 상품 페이지를 연다 |
| **일반의약품** | 가격 비교를 하지 않는다 (약사법상 온라인 판매 불가). 의약품은 지금처럼 허가 정보와 DUR만 보여 준다 |
| 순위 이름 | "효과 좋은 순"이라고 쓰지 않는다. **"함량·가격·신뢰 순"**처럼 기준을 드러내고, 제품마다 점수 이유를 보여 준다 |
| 문구 | "사세요", "추천" 같은 권유를 쓰지 않는다. 식약처 사실과 가격만 보여 준다 (건강기능식품 광고 규제) |
| 수익 링크 | 1단계에서는 넣지 않는다. 나중에 제휴 링크를 넣으면 "수수료를 받을 수 있음" 표시가 의무다 |
| 경쟁 앱 | 필라이즈는 다이어트·운동 쪽이라 방향이 다르다(사용자 판단). 우리 차이: 부모님용 큰 글씨, 식약처 검증, 내 약 충돌, 하루치 가격 |

## 진행 순서

### 0단계. 세팅 파일 정리 (10분)

1. 작업 브랜치를 만든다: `feat/supplement-search`
2. `/team-ai:setup`이 만든 파일을 사용자와 함께 훑어본다. 특히 `CLAUDE.md`의 검증 명령과 `.claude/settings.json`의 권한.
3. `/team-ai:commit`으로 "chore: Claude Code 팀 세팅"을 커밋한다. 이 문서(`docs/next-supplement-search.md`)도 같이 커밋한다.

**끝나면 멈추고 보고한다.**

### 1단계. 네이버 키 준비 (사용자가 함, 5분)

1. https://developers.naver.com → Application → 애플리케이션 등록 → 사용 API **검색**, 환경 **WEB**(`http://localhost`)
2. `web/.env`에 넣는다. 서버에서만 쓰므로 `VITE_` 접두사를 붙이지 않는다.
   ```
   NAVER_CLIENT_ID=...
   NAVER_CLIENT_SECRET=...
   ```
3. `web/.env.example`에 두 줄을 설명과 함께 추가한다(값은 비움). 이 작업은 Claude가 한다.
4. 키 값은 채팅에 붙여 넣지 않는다. Claude는 `.env`를 읽지 않는다.

### 2단계. 가능성 시험 (2~3시간) ← 가장 중요

이 기능이 될지 안 될지는 **식약처 제품과 네이버 상품이 제대로 연결되는가**에 달려 있다. 화면을 만들기 전에 이것부터 확인한다.

**입력**: 사용자가 정한 성분 5개 (아버지가 실제로 물어보신 것). 사용자에게 먼저 묻는다.

**시험 스크립트**: `scripts/gate-search/` 아래 Node 스크립트(의존성 없이 `fetch`). 나중에 `web/`에서 같은 논리를 다시 쓰기 쉽게 Node로 한다. 키는 `web/.env`에서 읽는다.

성분마다:
1. **식약처에서 제품 찾기**: 이 원료가 들어간 제품을 찾는다. 먼저 API가 원재료나 기능성으로 걸러 주는지 확인한다. 안 되면 품목 데이터를 페이지 단위로 내려받아 `scripts/gate-search/data/`에 JSON으로 저장한 뒤 로컬에서 찾는다(커밋하지 않음, `.gitignore`). 필드 이름은 첫 호출 결과로 확인하고 추측하지 않는다.
2. **제품마다 네이버 검색**: 상위 10개 제품에 대해 `query = 제품명 + 회사명`으로 검색한다.
3. **같은 제품인지 판정**: 먼저 규칙(회사명 포함, 핵심 단어 일치)으로 한다. 애매하면 Gemini로 판정하고, 판정 이유를 남긴다.
4. **기록**: 성분별로 식약처 제품 수, 네이버에서 찾은 수, 연결 결과(제품명, 회사, 최저가, 링크, 판정 근거)를 표로 정리한다.

**결과물**: `scripts/gate-search/RESULT.md` 표. 사용자가 링크를 눌러 맞는지 직접 확인한다.

**통과 기준**:
- 성분 5개 중 4개 이상에서, 판매 중인 제품을 3개 이상 찾음
- 사용자가 확인한 연결 정확도가 80% 이상

**멈춤 조건** (이럴 땐 진행하지 말고 보고한다):
- 식약처 데이터에 원재료나 함량 정보가 없어서 성분으로 제품을 찾을 수 없다
- 연결 정확도가 60% 미만이다
- 네이버 API가 건강기능식품을 거의 돌려주지 않는다

**끝나면 멈추고 결과를 보고한다.** 통과하지 못하면 다른 연결 방법(바코드, 품목보고번호 등)을 제안한다.

### 3단계. 설계 갱신 (선택, 30분)

통과하면 `/office-hours`로 `DESIGN.md`를 갱신한다. 이 앱은 "상호작용 체크"에서 "식약처 검증이 붙은 영양제 검색"으로 넓어진다. 시험 결과를 근거로 1단계 범위를 확정한다. 사용자가 건너뛰자고 하면 바로 4단계로 간다.

### 4단계. 계획

`/team-ai:plan-feature 1단계 영양제 검색: 성분 검색 → 판매 중 제품 목록(회사·제품명·가격·네이버 링크) + 함량·가격·신뢰 순 정렬 + 식약처 검증 + 회수 이력 + 내 약 충돌`

plan.md에 아래처럼 **따로 검증할 수 있는 작업**으로 나눈다(제안이며 plan-feature가 코드를 보고 조정한다).

1. `web/api/shop.ts`: 네이버 쇼핑 검색 프록시 Edge Function. `web/api/llm.ts`와 같은 방식. 응답 캐시 헤더 설정.
2. 성분 → 제품 찾기: 2단계에서 정한 방법(API 직접 또는 미리 만든 색인)으로 `web/src/lib/`에 만든다.
3. 제품 연결과 점수: 2단계 판정 논리를 옮기고, 아래 점수 초안을 적용한다. 점수 이유 문자열을 같이 돌려준다.
4. 회수 이력 조회: 식품안전나라 회수 정보.
5. 검색 결과 화면: `web/src/components/`에 새 화면. 기존 `SearchScreen.tsx`와 큰 글씨 토큰을 따른다. 제품 카드에 [네이버에서 보기], [리뷰 보러 가기], [내 약과 확인].
6. 내 약 충돌: 기존 `dur.ts`를 재사용한다.
7. 캐시: 같은 성분·제품의 결과를 Dexie에 하루 보관한다(스키마 버전 올림. 올리기 전에 멈추고 묻는다).

### 5단계. 구현과 검증

- plan.md 위에서부터 하나씩 구현한다. 하나 끝날 때마다 `/team-ai:verify`.
- 폰에서 직접 확인한다(`npm --prefix web run dev`, LAN). 가능하면 **아버지가 직접 써 보시는 것**까지가 완료 기준이다.
- 커밋은 `/team-ai:commit`, PR은 `/team-ai-extras:open-pr`(설치돼 있으면).

### 6단계. 디자인 (1단계 화면이 나온 뒤)

검색 결과가 앱의 중심이 되므로 홈 구조가 바뀐다. 기능이 동작한 다음 `/impeccable`로 전체 화면을 다시 본다. 기존 디자인 토큰(`--pc-*`)과 따뜻한 케어 톤은 유지가 기본이다.

## 순위 점수 초안 (2단계 결과를 보고 조정)

| 기준 | 비중 | 계산 |
|---|---|---|
| 식약처 인정 | 30 | 그 성분이 주된 기능성으로 인정됐으면 만점 |
| 함량 | 25 | 하루 섭취량 기준 성분 함량. 같은 성분 제품끼리 비교 |
| 하루치 가격 | 25 | 최저가 ÷ 섭취 일수. 싼 쪽이 높음. 용량을 못 읽으면 이 항목은 빼고 "가격 정보 부족" 표시 |
| 인기도 | 10 | 네이버 `sort=sim` 결과에서의 순서 (네이버가 판매량·리뷰를 반영해 정렬하므로 간접 반영) |
| 회수 이력 | 감점 | 회수·판매중지 이력이 있으면 맨 아래로, 빨간 표시 |

화면에는 "왜 이 순서인가"를 제품마다 한 줄로 보여 준다. 예: "함량 상위, 하루 ○○원, 회수 이력 없음".
